Built for readable systems

Brace-free syntax

Indentation and plain words — no braces, brackets, or parentheses. Humans and assistants can read the source.

Rules built in

on handlers, rule, and when are part of the language — not scattered imperative patches.

State machines

machine transitions are declared and checked so illegal states are caught early.

Invariants & tests

invariant and test blocks validate behavior before release; contradictory specs get clear errors.

Value semantics planned

Automatic reference counting and value semantics are the target memory model; the interpreter today uses a simpler runtime.

Web UI & APIs planned

Built-in app framework in a SwiftUI/React style — documented in planned examples, not yet in the compiler.

One tool

romit check, romit run, and romit test ship in a single binary — no toolchain zoo.

Why Romit

Romit started from a rules-driven trading bot where changing one rule broke another. Rules, stops, and state lived as scattered code — there was no way to see whole behavior or prove a change was safe.

Core idea: the specification is the program. Romit Kumar is building a general-purpose compiled language to eventually replace Python, Rust, and Go for everyday work — with AI-friendly, readable source the compiler checks instead of fragile generated code.

Getting started in three steps

Step 1

Install

Run the one-line installer for your OS and add ~/.romit/bin to PATH.

Step 2

Write

Create hello.rmt with say "Hello, world!" — or open the playground.

Step 3

Run & test

romit run hello.rmt for scripts; romit test program.rmt for specs with tests.

Try it online

Compile and run Romit in your browser — powered by WebAssembly, no install required.
